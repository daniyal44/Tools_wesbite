# Zevylo Agent Toolbook

The one doc to read before touching tools in this repo. It explains how a
tool is wired end-to-end, the exact files to edit, the gotchas that have
bitten past sessions, and how to generate/refresh per-tool docs.

> Per-tool reference files live in `docs/tools/<category>/<slug>.md` and are
> generated by `node scripts/generate-tool-docs.mjs`. **Edit the tool's
> definition, not the generated `.md`.**

---

## 0. The hard prerequisite: install deps first

The newer heavy dependencies (`pdf-lib`, `pdfjs-dist`, `heic2any`,
`@ffmpeg/ffmpeg`, etc.) are declared in `package.json` but may **not** be in
`node_modules` on a fresh checkout. Several tools (all PDF tools, HEIC
converter, some video/audio helpers) import them and will fail to build until
you run:

```bash
npm install
```

If a build error says a module can't be resolved, check whether it's one of
these and whether install has actually run — don't "fix" the import.

## 1. Architecture in one screen

```
src/
  lib/tools/
    types.ts          # ToolDefinition + ToolCategory (the contract)
    registry.ts       # in-memory Map; register/search/related helpers
    categories.ts     # category metadata (name, color, icon, order)
    component-map.tsx  # slug -> dynamic(() => import(component))   [CLIENT]
  tools/
    <category>/
      index.ts                 # imports every *.definition, registers them
      <slug>.definition.ts     # metadata for ONE tool (SEO, FAQ, flags)
      <slug>.tsx               # the actual React component (UI + logic)
    index.ts          # imports every category index (side-effect registration)
  components/tools/
    tool-icon.tsx     # slug -> lucide icon component
```

A tool is **"registered"** purely by importing its definition in the category
`index.ts`. A tool is **"renderable"** only if its slug also exists in
`component-map.tsx`. A tool **"looks right"** only if its slug also exists in
`tool-icon.tsx`. Miss any of the three and you get a silent gap, not a crash.

## 2. Add a new tool — the 5-touchpoint recipe

Do all five, in this order. (This is exactly how the most recent tools —
`text-repeater`, `markdown-previewer`, `number-to-words`,
`average-calculator`, `xml-formatter` — were added.)

**Step 1 — Component** `src/tools/<category>/<slug>.tsx`
- `'use client';` at the top.
- `export default function PascalCaseName() { ... }`.
- Client-only logic. Import clipboard via `import { copyToClipboard } from '@/lib/utils';`
  (it returns `Promise<boolean>`).
- Theme every surface: pair light + `dark:` classes on text, bg, and borders.
  A `text-zinc-200` with no `dark:` is invisible on white — a recurring bug.

**Step 2 — Definition** `src/tools/<category>/<slug>.definition.ts`
- `export const <camel>Definition: ToolDefinition = { ... }`.
- `id === slug === component` by convention. `category` must be a valid
  `ToolCategory` (see `types.ts`). Fill `seo`, `keywords`, `searchableText`,
  2–3 `faq`, and `relatedTools` (real slugs).
- Pick a `sortOrder` higher than the current max in that category.

**Step 3 — Category index** `src/tools/<category>/index.ts`
- `import { <camel>Definition } from './<slug>.definition';`
- Add it to **both** the `const <category>Tools = [ ... ]` array **and** the
  `export { ... }` block.

**Step 4 — Component map** `src/lib/tools/component-map.tsx`
```ts
'<slug>': dynamic(() => import('@/tools/<category>/<slug>'), {
  ssr: false, loading: LoadingFallback,
}),
```

**Step 5 — Icon map** `src/components/tools/tool-icon.tsx`
- `'<slug>': SomeLucideIcon,` — make sure that icon is imported at the top of
  the file (most common ones already are).

Then regenerate docs (`node scripts/generate-tool-docs.mjs`) and build.

## 3. No duplicates

Every `slug` must be unique across the whole repo. Before adding, grep:
```bash
grep -rn "slug: '<slug>'" src/tools
```
The doc generator also prints `DUPLICATE slug "..."` warnings and a dupe count
on every run — treat a non-zero count as a build-blocking error.

## 4. Known hazards (verified this session)

- **PDF tools (all of them)** depend on `pdf-lib` / `pdfjs-dist`. They are
  dead until `npm install` runs. Not a code bug — an install gate.
- **GIF encoder** (`src/lib/utils/gif-encoder.ts`): the LZW width-bump test
  `nextCode > (1 << codeSize)` *looks* like an off-by-one but is **correct** —
  the encoder emits-then-assigns while a decoder lags one code behind, so
  widths stay in lockstep. Do **not** change it to `>=`; that introduces the
  desync it appears to avoid.
- **Light-mode invisibility**: several components historically used
  `text-zinc-*` / `text-gray-*` with no `dark:` counterpart (or vice-versa),
  rendering near-invisible on one theme. When editing any component, verify
  both themes.
- **Facade risk**: a few AI/marketing tools used to emit the same canned
  output regardless of input. The article generator
  (`src/lib/articles/article-generator.ts`) now genuinely branches on
  topic/audience/tone and is honestly labeled as a local draft. Keep tools
  honest: output must reflect input, and claims must match behavior.

## 5. Never delete

Standing rule for this repo: **never delete** tools, files, or features.
Fix in place. If something looks redundant, prefer merging or hiding
(`status: 'disabled'`) over removal, and only with explicit sign-off.

## 6. Verify before you claim done

1. `npm install` (if not already).
2. `node scripts/generate-tool-docs.mjs` — 0 duplicate slugs.
3. `npm run build` (or `npm run lint` + `npm run typecheck` if present) — must
   pass. TypeScript will catch a missing component-map/icon-map entry only at
   runtime, not compile time, so also spot-check the new tool renders.
4. Report what actually passed. If the build didn't run, say so.
